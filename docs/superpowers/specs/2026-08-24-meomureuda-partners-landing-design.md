## 1. 목표와 경계

이 페이지의 1차 독자는 Agoda, Booking.com 및 숙소 데이터 공급사의 API·사업 제휴 담당자다. 페이지의 단일 핵심 역할은 담당자가 머무르다의 서비스 실체, 사용자 가치, 요청 데이터 범위, 초기 운영 모델과 개발 상태를 빠르게 이해하고 이메일로 제휴 논의를 시작하게 하는 것이다.

이 작업은 기존 Expo 앱과 완전히 분리한다.

- 기존 `C:\dev\meomureuda-frontend-app`의 파일, 라우터, 패키지, 환경변수, 빌드 설정 및 배포 주소를 변경하지 않는다.
- 새 랜딩페이지는 별도 폴더, 별도 Git 저장소, 별도 Vercel 프로젝트로 관리한다.
- 기존 앱 컴포넌트는 import하지 않는다.
- Figma는 화면·브랜드 참고 및 원본 에셋 추출에만 사용한다.
- 필요한 이미지와 캐릭터는 Figma에서 새 프로젝트의 `public` 디렉터리로 복사해 독립 보관한다.
- Agoda와 Booking.com은 텍스트로만 언급하고, 로고·상표 그래픽은 사용하지 않는다.
- 모든 제휴 관련 표현은 `연동 검토 대상`, `협의 중`, `초기 모델`, `예정`으로 한정한다.

## 3. 레퍼런스 분석과 독립성 원칙

### Opuola에서 참고할 원리

[Opuola](https://www.behance.net/gallery/83903129/Opuola)는 Behance에서 Illustration·Branding으로 분류된 수공예 장식 브랜드 리디자인이다. 원본의 이미지·레이아웃·로고·패턴을 가져오지 않고 다음 추상적 원리만 참고한다.

- 넓은 여백과 큰 제목이 만드는 느린 호흡
- 사진, 유기적 도형, 손맛 있는 그래픽을 겹치는 편집 방식
- 매끈한 디지털 UI보다 인쇄물과 여행 잡지에 가까운 질감
- 따뜻한 주조색과 제한된 자연색 보조 팔레트
- 반복되는 곡선과 비정형 경계가 만드는 휴양지의 리듬

Behance 페이지에 표시된 저작권 조건을 존중해 Opuola의 고유 자산을 추출·복제·변형하지 않는다.

### 제주로 번역하는 방식

- 열대 과일 대신 감귤과 감귤 잎
- 야자수와 열대 산 대신 오름, 곶자왈, 억새의 실루엣
- 백사장 중심 해변 대신 현무암이 보이는 제주 해안
- 휴양지 장식 대신 제주 우편엽서, 날짜 도장, 지도 표식, 여행 기록지
- 열대 캐릭터 대신 Figma의 머무르다 새싹 캐릭터
- 반복 패턴 대신 돌담의 불규칙한 리듬과 바람을 닮은 선

## 4. 시각 디자인 시스템

### 디자인 명제

`여행자의 생활 성향을 기록한 제주 체류 노트가, 숙소 데이터 제휴 제안서로 이어진다.`

일반 소비자에게는 따뜻하고 친근하게 보이되, 제휴 담당자에게는 개발 상태와 데이터 흐름이 정확히 읽혀야 한다. 감성 사진과 캐릭터는 서비스 경험을 설명하고, 정보 구조와 문구는 사업 검토를 돕는다.

### 고유한 시각 장치

페이지가 기억될 한 가지 장치는 **`28—60박 제주 체류 기록선`**이다.

- 히어로에서 `28—60`을 대형 활자로 배치하고 제주 바람을 닮은 얇은 선이 숫자 사이를 잇는다.
- 이 선은 이용 흐름의 4단계, 데이터 연동 다이어그램, 개발 일정의 시간축으로 형태를 바꾸며 이어진다.
- 숫자는 장식이 아니라 서비스 대상 체류 기간을 즉시 전달한다.
- 데스크톱에서는 이미지 뒤로 일부가 잘리는 대형 편집 타이포그래피로, 모바일에서는 우편 소인 형태의 작은 세로 배지로 축약한다.
- 의미는 본문에도 반복해 스크린 리더와 작은 화면에서 손실되지 않게 한다.

### 색상 토큰

| `paper` | `#F7F1E5` | 기본 크림 배경 |

오렌지는 전체 배경이 아니라 CTA, 현재 단계, 핵심 문장과 작은 스탬프에 집중한다. 긴 본문 배경은 `paper`와 `white`, 데이터 섹션은 옅은 바다색과 `forest`를 사용한다. 그라데이션, 유리 효과, 네온, 3D 아이콘은 사용하지 않는다.

### 타이포그래피

- 제목: `MaruBuri` Bold/SemiBold. 제주 여행기와 인쇄물의 온기를 주되, 히어로와 섹션 제목에만 제한한다.
- 본문·내비게이션·데이터: `Pretendard Variable`. 긴 한국어와 숫자, 상태 표기를 빠르게 읽도록 한다.
- 폰트는 라이선스를 확인한 뒤 필요한 굵기만 로컬 호스팅하고 `font-display: swap`을 적용한다.
- 기본 본문은 모바일 16px/1.7, 데스크톱 17px/1.75를 사용한다.
- 히어로 제목은 `clamp(2.7rem, 6.5vw, 6.6rem)`로 잡되 한글 자간을 과도하게 줄이지 않는다.
- 상태, 날짜, 배지에는 Pretendard의 tabular numeral과 넉넉한 자간을 사용한다.

### 형태와 질감

- 사진 프레임은 한쪽 모서리만 크게 휘는 비대칭 형태를 섞어 사용한다.
- 모든 정보를 둥근 카드로 만들지 않는다. 표, 종이 띠, 큰 인용문, 사진 캡션, 선형 다이어그램을 섞는다.
- 종이 질감은 작은 투명도 PNG 또는 CSS 노이즈 한 겹으로만 표현하고 본문 대비에 영향을 주지 않는다.
- 돌담, 감귤 잎, 바람 선은 직접 만든 단순 벡터 모티프로 사용하되 Opuola 패턴을 본뜨지 않는다.

## 6. 섹션별 상세 설계와 카피

### 6.1 헤더

- 왼쪽: Figma에서 추출한 머무르다 새싹 심볼과 워드마크
- 가운데: `서비스 소개`, `이용 흐름`, `데이터 연동`, `개발 현황`, `프로젝트 정보`, `문의하기`
- 오른쪽: 외곽선형 `서비스 미리보기 ↗`
- 데스크톱에서는 크림색 불투명 고정 헤더와 얇은 현무암색 구분선을 사용한다.
- 모바일에서는 로고와 메뉴 버튼만 보이고, 펼친 메뉴는 완전 불투명한 종이색 패널로 제공한다.
- 각 내비게이션 링크는 섹션 앵커로 이동하며 키보드 포커스가 분명해야 한다.

### 6.2 히어로

**눈썹 문구**

`제주 28–60박 장기 체류 추천 서비스`

**핵심 문구**

`나에게 맞는 제주에서, 한 달을 살아보다`

**설명**

`여행 성향 진단을 통해 나에게 맞는 제주 권역과 장기 체류 숙소를 추천하는 제주 한달살이 서비스입니다.`

**프로젝트 배지**

`2026 관광데이터 활용 공모전 출품 프로젝트`

**CTA**

- 주 CTA: `제휴 및 데이터 연동 문의` → 이메일 작성 화면
- 보조 CTA: `서비스 미리보기 ↗` → Figma 프로토타입 새 탭

**시각 구성**

- 왼쪽은 큰 제목과 CTA, 오른쪽은 제주 바다·현무암 해안 사진 위에 Figma 캐릭터와 진단·홈 화면 일부를 우편엽서처럼 겹친다.
- `28—60` 대형 숫자가 사진 뒤에서 일부 드러나며 체류 기간을 기억시키는 서명 장치가 된다.
- 사진 위에 긴 텍스트를 직접 올리지 않고, 별도의 크림색 면을 사용해 가독성을 보장한다.

### 6.3 서비스가 해결하는 문제

**섹션 문장**

`한 달이라는 시간에는, 호텔 검색만으로 부족합니다.`

다음 네 문제를 두 열의 편집 지면으로 구성한다.

1. `생활권 비교의 어려움` — 제주 권역별 교통, 편의시설, 분위기를 한눈에 비교하기 어렵습니다.
2. `분산된 숙소 탐색` — 한달살이 숙소 정보가 여러 예약·단기임대 플랫폼에 흩어져 있습니다.
3. `장기 체류 가격의 불투명성` — 일반 숙박 가격과 28–60박 장기 체류 가격의 차이를 파악하기 어렵습니다.
4. `성향과 지역을 잇는 추천 부족` — 여행자의 생활 성향과 제주 지역 특성을 함께 고려한 추천이 부족합니다.

각 항목은 동일한 카드가 아니라 번호가 찍힌 종이 띠, 짧은 설명, 제주 생활 사진의 일부를 엇갈리게 조합한다.

### 6.4 이용 흐름

`28—60박 기록선`이 실제 순서를 나타내는 네 단계 연결선으로 바뀐다.

1. **여행 성향 진단 — 핵심 기능**
   - 선호 풍경, 생활 리듬, 이동 방식 등을 진단합니다.
   - Figma의 진단 1 화면과 선택 이미지 일부를 사용합니다.
2. **맞춤 제주 권역 추천 — 핵심 기능**
   - 진단 결과와 권역별 생활 특성을 연결해 머물 지역을 제안합니다.
   - 홈 화면의 `감성 충전가형`, 권역 추천 영역을 사용합니다.
3. **장기 체류 숙소 확인 — 개발 중**
   - 일정, 인원, 권역 조건에 맞는 숙소와 가격·공실 정보를 확인합니다.
4. **커뮤니티와 여행 일지 — 보조 기능**
   - 체류 경험을 나누고 기록합니다.
   - 커뮤니티는 `개발 중`, 여행 일지는 `후속 개발 예정` 상태를 화면에 함께 표시합니다.

## 8. 반응형과 인터랙션

### 레이아웃

- 모바일 우선으로 작성한다.
- 콘텐츠 최대 폭: `1200px`
- 기본 좌우 여백: 모바일 `20px`, 태블릿 `32px`, 데스크톱 `48px`
- 주요 전환점: `48rem`과 `70rem`; 콘텐츠가 깨지는 실제 지점에 따라 미세 조정한다.
- 320px 너비에서도 가로 스크롤이 없어야 한다.
- 데이터 다이어그램과 개발 표는 모바일에서 세로 흐름으로 재배치하며 단순 축소하지 않는다.

### 모션

- 스크롤 진입: `opacity`와 `translateY(12px)`를 380–480ms 안에서 한 번만 실행
- 히어로 이미지: 데스크톱 포인터 환경에서 최대 8px 범위의 느린 이동
- 버튼: 눌림과 포커스에 1–2px 이동 또는 색 변화
- 데이터 연결선: 섹션 진입 시 한 번만 그려지는 효과
- `prefers-reduced-motion: reduce`에서는 이동·선 그리기·부드러운 스크롤을 제거하고 즉시 표시
- 콘텐츠를 읽기 위해 애니메이션 완료를 기다릴 필요가 없어야 한다.

## 9. 기술 설계

### 스택

- Next.js App Router 최신 안정 버전
- React + TypeScript strict mode
- CSS Modules와 전역 디자인 토큰
- `next/image`, `next/font/local`
- Playwright 기반 데스크톱·모바일 시각 검수 및 핵심 링크 검사
- Vercel 별도 프로젝트 배포

Tailwind 또는 대형 UI 프레임워크는 도입하지 않는다. 이 페이지는 고유한 편집 레이아웃이 핵심이며, 작은 독립 프로젝트에서 CSS Modules가 스타일 충돌과 불필요한 의존성을 줄인다.

각 섹션은 하나의 목적을 가지며, 반복 콘텐츠와 상태는 `siteContent.ts`에서 타입이 지정된 데이터로 관리한다. 기존 앱 코드와 공유 패키지는 만들지 않는다.

페이지에는 서버 데이터나 사용자 입력 폼이 없다. 문의 CTA는 `mailto:`를 사용하며 개인정보를 수집·저장하지 않는다. 따라서 초기 배포에는 백엔드, 쿠키 또는 데이터베이스가 필요 없다.

- 무의미한 장식 숫자 대신 서비스의 실제 조건인 `28—60박`을 시각 시스템의 중심에 둔다.

- 감성 사진만 나열하지 않고 파트너가 검토해야 할 데이터 공급 후보와 상태를 페이지 중반의 핵심 지면으로 배치한다.
- 열대 휴양지 패턴 대신 현무암 해안, 오름, 돌담, 바람 선을 사용한다.
- 캐릭터는 장식이 아니라 진단과 추천 흐름을 안내하는 역할로 제한한다.

### 의도적인 미적 위험

히어로의 대형 `28—60` 숫자를 일부 잘린 편집 활자로 사용하는 것이 유일한 강한 시각적 위험이다. 체류 기간을 즉시 기억시키고 여행 잡지 같은 인상을 주기 때문에 목적에 부합한다. 나머지 요소는 차분한 여백, 정확한 상태 표현과 제한된 모션으로 절제한다.

### 모순·모호성 점검 결과

- 서비스 미리보기 대상은 제공된 Figma 프로토타입으로 확정했다.
- 제휴 문의는 이메일 CTA로 확정했다.
- 앱 내 예약·결제는 초기 모델에서 제외했다.
- 커뮤니티는 개발 중, 여행 일지는 후속 개발 예정으로 구분했다.
- Agoda·Booking.com은 연동 검토 대상이며 제휴사가 아니다.
- 기존 앱 프로젝트와 새 랜딩 프로젝트 사이에는 코드 의존성이 없다.
